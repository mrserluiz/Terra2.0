# Terra2 7.3.5-BETA — biome edit recovery and truthful diagnostics

Targets the independent engine on Paper 26.2 / Java 25. Native Paper 26.3 support is not established by the thin-controller compatibility job.

## Changes

- Explicit `/terra2 setbiome` chunk PDC overlays remain readable after a pack fingerprint/version change only if the world UUID, seed, chunk, vertical bounds, pack ID and every saved biome identity/reference still match. Unknown or removed IDs and foreign/corrupt payloads remain refused intact. A later explicit edit rebases the preserved sparse overlay to the current fingerprint.
- When a chunk with a saved edit loads, a bounded main-thread queue restores only its explicit edited cells to the real registered biome (or the configured vanilla reference in VANILLA_COMPATIBLE worlds). One chunk is processed per tick, only loaded chunks, at most 512 pending. Matching cells cause no write or resend. The overlay is retained unchanged. No terrain, blocks or structures are regenerated. Protected worlds remain refused.
- Manual recovery of the current chunk: `/terra2 biome restore`. This is not a reconstruction of unsaved historical edits. Custom IDs must still be present in the installed pack.
- CUSTOM position/discovery reads use the actual chunk biome, rather than predicting a historical identity using the current pack's provider. A vanilla cell with no saved edit is reported as unknown to Terra2 instead of being falsely labeled as a custom biome.
- `/terra2 biome debug` shows actual registered biome, identity source, position, saved overlay validity and vertical extent, plus the looked-at block's biome and height. `/terra2 bedrock debug` can show the real biome even when the optional Bedrock catalog is unavailable.
- Biome and Bedrock command messages use the requested green/white/brown `■Terra.2:` prefix through Adventure components. Causes and IDs stay literal; `&` inside diagnostics cannot inject formatting. Existing server log tags/stack traces are retained.
- Resource-pack manifest/header/module version advances to 7.3.5; user calibration is preserved.

## Selection and third-party edits

`/terra2 setbiome <ID>` continues to use a WorldEdit/FAWE **cuboid** and its full X/Y/Z bounds, snapped to the vanilla 4×4×4 biome grid. It does not implicitly extend to the sky or bedrock. Leaves above the selection are not edited. Limits remain 4096 biome cells / 64 loaded chunks. A full-height selection may exceed the cell limit and must be split.

The saved Terra2 overlay is authoritative on the next chunk load. An external `//setbiome`, brush, paste or season plugin that later changes those same cells does not update this overlay. A new Terra2 edit is the supported way to change its saved target. There is no continuous repainting loop and no WorldEdit undo integration.

Seeing distant color and losing it nearby does not by itself identify the cause. Compare actual chunk IDs at the player's height and at the foliage, then the saved overlay. This build does not claim a verified fix for all Java/Bedrock client renderers or a proven conflict with FastAsyncVoxelSniper.

## Installation

Stop the server, move previous Terra2 JARs out of `plugins`, install only `Terra2-bukkit-7.3.5-BETA.jar`, retain `plugins/Terra2`, packs and world saves, then start. Do not install the ZIP or the thin controller alongside this engine. Visit an edited area to load its chunk and run `/terra2 biome debug`.
