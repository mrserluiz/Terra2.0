# Terra2 7.3.2-BETA

## Cor-base com calibração global e por bioma

O campo `color` agora define a **cor-base**. Saturação, brilho e tom são aplicados depois para produzir o RGB final do pack Bedrock. Na 7.3.1, `color` ignorava HSV; nesta versão os campos trabalham juntos.

Arquivo: `plugins/Terra2/bedrock/color-calibration.yml`.

```yaml
roles:
  foliage: {saturation: 1.25, brightness: 1.0, hue-degrees: 0.0}
  grass: {saturation: 1.20, brightness: 1.0, hue-degrees: 0.0}
  water: {saturation: 1.15, brightness: 1.0, hue-degrees: 0.0}
biomes:
  'terra:hydraxia/hydraxia/autumnal_woodlands':
    foliage:
      color: '#FF6A19'
      saturation: 1.10
      brightness: 1.0
      hue-degrees: 0.0
  'terra:hydraxia/hydraxia/sakura_woodlands':
    foliage:
      color: '#FF99CC'
      saturation: 1.40
      brightness: 1.0
      hue-degrees: 0.0
```

Cada campo definido no bioma substitui somente o mesmo campo global; campos omitidos herdam os valores globais. Valores globais e locais **não são multiplicados entre si**. Sem ambos, os padrões são saturação 1.0, brilho 1.0 e tom 0.0; a base é a cor do pack original. Uma cor-base global também é herdada quando o bioma não define outra. Folhagem, grama e água podem ser configuradas individualmente nos dois níveis.

Para enviar um hexadecimal exato sem ajuste, defina explicitamente saturação/brilho 1.0 e tom 0.0 naquele papel/bioma. **Migração:** entradas antigas contendo apenas `color` agora recebem o HSV global. Confira esses casos antes do teste. O plugin preserva o arquivo existente, sem reescrevê-lo nem remover campos.

O RGB final tem canais limitados a 0..255; a saturação HSV e o brilho resultantes são limitados a 1. Saturação/brilho configurados aceitam 0..2; tom aceita -30..30 graus. Intensificar uma cor já saturada pode não produzir diferença. A imagem do Java continua sendo referência; o hexadecimal enviado não garante pixels idênticos entre clientes, iluminação e texturas.

## Conferir no jogo

```text
/terra2 bedrock debug
```

O debug e `plugins/Terra2/bedrock/color-report.yml` mostram **original, base e final**, os valores HSV efetivos e o modo `BIOME_BASE_COLOR_HSV` ou `GLOBAL_BASE_COLOR_HSV` quando há uma base explícita. O escopo indica o conjunto efetivo do papel; ele pode conter campos herdados. O relatório passa ao schema 2 e registra `BASE_THEN_EFFECTIVE_HSV`, mantendo UUID/versão/hash do pack compilado.

Mantidas a validação de IDs exatos, a recusa de YAML inválido e a identificação de leituras previstas versus persistidas. A compilação atua somente na apresentação Bedrock; os perfis Java e o terreno não são alterados. O debug não confirma aceitação/renderização no cliente.

## Atualização

Substitua o JAR com o servidor desligado. Reinicie após alterar o YAML e reconecte/aceite o pack recompilado. O manifesto e o módulo desta build usam `[7,3,2]`. O pack oferecido automaticamente é gerado a partir do catálogo e dos ajustes do seu servidor. Não use o pack da fixture de CI como calibração recomendada.

Motor: **Paper 26.2 / Java 25**. Ponte nativa: mundo CUSTOM e **Geyser-Spigot oficial 2.11.3 build 1251**. O contrato do Geyser 2.12 ainda não é suportado. Esta atualização não corrige um travamento sem diagnóstico nem altera a distribuição de terreno dos packs.

## Validação

Compilação e testes pendentes nesta revisão inicial. Os testes verificam herança campo a campo, substituição sem multiplicação, cor-base seguida de HSV, perfis originais preservados, canais RGB e consistência do relatório com o client biome gerado. A integração Paper/Geyser confere cor-base e final no pack registrado após inicialização/reinício.
